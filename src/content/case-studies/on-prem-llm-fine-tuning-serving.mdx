## Executive Summary

Strict enterprise data security regulations prohibited sending confidential enterprise documents to cloud LLM APIs. However, running unquantized 70B parameter models required unsustainable GPU infrastructure spending.

We designed a standardized, self-serve QLoRA fine-tuning and **vLLM** serving pipeline that enabled product teams to train and deploy specialized 8B/70B models on a single on-premise A100 GPU node, increasing entity extraction F1 score from 81% to 96%.

---

## Technical Stack & Engineering Highlights

### 1. 4-bit NF4 QLoRA Fine-Tuning Pipeline
- Leveraged **PyTorch**, **Hugging Face PEFT**, and BitsAndBytes for 4-bit NormalFloat quantization.
- Trained rank-16 LoRA adapters targeting query, key, value, and projection layers.

### 2. vLLM Multi-Adapter Serving
- Deployed **vLLM** with PagedAttention to serve multiple fine-tuned adapter weights dynamically over a single base model checkpoint.
- Enabled instantaneous adapter swapping without reloading base model weights in VRAM.

### 3. Self-Serve Developer CLI & Docker Tooling
- Containerized the fine-tuning pipeline into a single CLI tool (`afiniti-llm-train`) that automated dataset validation, LoRA training, and evaluation metric logging.

---

## Business Impact

- **96% Extraction F1 Score**: Achieved domain-specific accuracy exceeding GPT-4 on structured enterprise document extraction.
- **78% Reduction in Deployment Cycle**: Reduced model fine-tuning and production deployment timeline from 6 weeks to 9 days.
- **45% Memory Savings**: Enabled 4 concurrent specialized model adapters on a single 80GB A100 GPU.
